## Key Insights

### Current Limitations Addressed

1. **Isolated Chunk Retrieval**
   - Traditional RAG retrieves chunks independently
   - **Solution**: Knowledge graphs capture relationships (KG²RAG)

2. **Static Retrieval Strategy**
   - Single-turn retrieval regardless of query complexity
   - **Solution**: RL-based adaptive multi-turn retrieval (RouteRAG)

3. **Semantic-Only Approaches**
   - Ignore fact-level relationships in knowledge
   - **Solution**: Graph-based chunk organization

## Technical Architecture Patterns

### Basic RAG Architecture

```

                                      ↓
                                   Generator → Response
```

### Graph-Enhanced RAG (KG²RAG)

```

       ↓                           ↓
    Chunk Organization        Retrieved Context
                                      ↓
                                   Generator → Response

```
Query → RL Router → [Text Retriever OR Graph Retriever OR Both]
                      ↓                    ↓

## Mathematical Foundations

### Standard RAG Formulation

The standard RAG formulation computes the response probability as:

```
P(y|x, D) = Σ P(y|x, z) · P(z|D, x)
```

Where:
- `y`: Generated response
- `x`: Input query
- `D`: Knowledge base
- `z`: Retrieved documents/chunks
- `P(z|D, x)`: Retrieval probability
- `P(y|x, z)`: Generation probability given retrieval

### Graph-Enhanced RAG (KG²RAG)

KG²RAG incorporates knowledge graph structure:

```
P(z|D, x, G) = P(z|D, x) · α(G, z)
```

Where:
- `G`: Knowledge graph
- `α(G, z)`: Graph-aware scoring function

### RL-Based Routing (RouteRAG)

RouteRAG uses reinforcement learning to optimize routing:

```
π(a|s) = argmax_a Q(s, a)
```

Where:
- `π`: Routing policy
- `s`: Current state (query, context)
- `a`: Action (retrieve from text, graph, or both)
- `Q`: Q-function learned via RL
